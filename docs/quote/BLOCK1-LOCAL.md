# Marocora — Block 1 local regular translation

**Current startup/scanner instructions:** use `BLOCK16-CLOUDMERSIVE.md`.
Block 1.6 requires an owner-supplied environment key and defaults local workflow
switches OFF; the older launcher/ClamAV instructions below are historical.

**Block 1.5 supersedes the upload-format/size/scanning notes below.** Read
`BLOCK15-LOCAL.md` for the current PDF/DOCX/JPG/PNG support, 10 MB limit and
mandatory quarantine when ClamAV is absent. The original Block 1 notes are kept
below as historical implementation context; they do not describe current limits.

Run `node server/block1/start.mjs` from this checkout with native PostgreSQL 17
tools installed. `QUOTE_PG_BIN` may point to another trusted PostgreSQL 17 binary
directory. No database URL, Supabase credential, mail key or production connection
is accepted. Do not apply `server/block1/local.sql` to a managed project.

The launcher creates private synthetic state in `tmp/block1-private`, creates a
short private Unix-socket directory, disables PostgreSQL TCP, and binds the web
server only to `127.0.0.1:4197`. It prints one-use local sign-in links for customer,
staff and provider. Use separate browser profiles for simultaneous roles. A
restart invalidates sessions and prints new one-use links; stored requests,
documents, quotes, acceptance and queued notifications persist. Ctrl-C stops both
local services. The saved migration hash refuses incompatible automatic upgrades.

The local migration composes the unchanged quote SQL drafts inside a committed
local transaction, then adds Block 1 capture, file access, staff issuance and
queued-only notification handling. Its explicit database/session-owner guard
rejects other targets. All three local DB switches are ON. Exported production
defaults and the original draft rollback guards remain OFF/unchanged.

## Test the flow

1. Customer: open local sign-in link, submit `translation-request.html` with a
   regular service and optionally a UTF-8 `.txt` document (1 MiB maximum, five
   documents per request via API). The form supports one selected file per submit.
2. Staff: open `translation-workspace.html`, inspect customer details/document,
   and invite the synthetic translator. Only the staff owner sees customer
   contact details. An unrelated staff member has no document access.
3. Provider: accept the invitation to assess; only then can they view documents.
4. Staff: issue a quote with exact integer-minor-unit total, currency, scope,
   turnaround, exclusions, revisions, expiry and terms. Staff remains the recorded
   issuer; the assigned translator remains the provider. Each offer freezes the
   document IDs, names, sizes and hashes. New uploads lock after any quote.
5. Customer: open/refresh the workspace, review the complete quote and synthetic
   policy, tick the explicit agreement box, then accept. Reload to recover the
   saved acceptance. No work, booking, charge or payment is activated.

Run `node --test tests/block1.test.mjs` for actual local HTTP/PostgreSQL/file tests.
Local PostgreSQL shared memory/socket binding can require executor escalation.
No fixture-shim bypass is installed. Role claims are generated by the isolated
local server, using one-use random tickets and HttpOnly SameSite cookies with
CSRF/origin/Host checks. This is not managed Supabase JWT verification.

## Boundaries

Uploads accept UTF-8 text only: no PDF, DOCX, images, OCR or archive parsing. Invalid
UTF-8, control/binary content, oversized files, traversal names and the standard
antivirus test marker are rejected. This is not an antivirus scanner. Downloads
use attachment disposition and nosniff; inline text previews use textContent.
Storage is private to the local OS account (0700 directories, 0600 documents),
not encrypted application storage. Only the current staff owner and eligible,
accepted assigned translator can retrieve bytes through the application. The
customer can upload but cannot retrieve bytes, as explicitly requested.

Notifications are frozen pending DB rows, not sent messages. No dispatcher or
mail transport exists here. The customer sees the quote in the workspace after
refresh, not by email or push. Intake capture does not call existing Formspree.
Only synthetic local policies/providers are seeded; no commercial terms, real
provider consent or legal enforceability has been approved or established.

The new workspaces are English only. Existing four-language public copy, Tanya's
hidden listing/test notice, mail workflows, permanent exclusions, worker/backup
systems and production infrastructure are preserved. Local UI assets live under
`server/block1/ui` and are excluded from the public static artifact. The file
input in the existing public source stays hidden and disabled; only this local
server injects the local handler. Its CSP blocks fallback submission to production.

Do not expose this local server or use it for real customer documents. No
production deployment, managed migration, sworn translation, live interpretation,
payments, settlement or Block 2 work is authorized by this implementation.
